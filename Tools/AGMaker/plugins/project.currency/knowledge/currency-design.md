# 货币设计指南（project.currency）

> 适用范围：RpgDemo 项目货币体系的设计与调参。配合 `currency-schema.md`（字段约束）使用。

## 何时使用

- 规划项目货币种类（免费/付费/活动币）与层级时。
- 设定基准货币、决定用「基准锚定」还是「定向兑换对」时。
- 评估兑换是否会导致通胀、需要多少手续费时。

## 核心模型：基准货币锚定

本插件用**基准货币锚定**而非 N×N 兑换矩阵：

- 选定一种货币为**基准**（`baseCurrencyId`），其 `unitValueInBase = 1`。
- 其他货币用 `unitValueInBase` 表达「1 单位值多少基准货币」。
- 任意两种货币的兑换 = 各自换算成基准再换算过去，自动得出比率。

**好处**：新增一种货币只需设一个 `unitValueInBase`，不用维护 O(N²) 兑换对。

### 示例：金币（基准）+ 钻石

- `CUR_gold`：`unitValueInBase = 1`（基准）
- `CUR_gem`：`unitValueInBase = 100`（1 钻石 = 100 金币）
- 试算：100 金币 → 钻石 = 100×1/100 = **1**；1 钻石 → 金币 = 1×100/1 = **100**

## 何时用定向兑换对（overrides）

基准锚定给出的是「等价值」兑换。以下场景用 `overrides` 覆盖：

1. **兑换损耗**：付费货币换回免费货币通常要打折。例：1 钻石锚定 100 金币，但 override 设 `rate=98` + `feeRate=0.02`，玩家实际到手更少，防刷。
2. **单向限制**：只想允许「钻石→金币」不允许反向，就只配这一条 override（反向无 override 时走基准锚定，若无基准则报 `EXCHANGE_NO_PATH`）。
3. **活动汇率**：限时优惠兑换。

## 精度（precision）与防通胀

- 兑换结果按**目标货币 precision 向下截断**，天然防增发。
- 免费货币（金币）通常 `precision = 0`（整数）。
- 付费货币若想支持「0.5 钻石」可设 `precision = 1~2`，但多数游戏付费货币也用 0。
- 截断意味着玩家兑换总会「吃亏一点」——这是设计意图，不是 bug。

## 常见反模式

- ❌ 把基准货币的 `unitValueInBase` 设成非 1 → 基准锚定换算直接报错。
- ❌ 为每对货币都配 override → 退化成难以维护的矩阵；优先用基准锚定。
- ❌ 付费货币能无损耗换回免费货币 → 工作室刷金通道。
- ❌ 新增货币后忘记 `set_base_currency`（若它是第一种货币）→ 兑换报 `EXCHANGE_NO_PATH`。

## 设计检查清单

1. 选哪种货币当基准？（通常是最高频的免费货币，如金币）
2. 每种货币的 `unitValueInBase` 反映真实价值比吗？
3. 付费→免费方向是否需要 override + feeRate 做损耗？
4. 各货币 precision 是否符合展示习惯？
5. 用 `quote_exchange` 实测几个典型金额，确认 net 符合预期。
